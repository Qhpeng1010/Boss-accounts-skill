# Boss Ledger Business Rules

## 1. 文件职责

本文件是 Boss Ledger 的业务层规则源，只定义：

- 业务对象与字段语义
- 页面类型选择
- 业务状态与状态流转
- 权限与敏感操作
- 业务校验
- 查询、统计和操作的业务含义
- 提交后的业务结果
- AI 生成时的业务完整性约束

颜色、字号、间距、布局、Ant Design 组件选型和交互样式统一进入 [`director-rules/01-visual-constitution.md`](./director-rules/01-visual-constitution.md) 和 [`director-rules/03-interaction-acceptance-rules.md`](./director-rules/03-interaction-acceptance-rules.md)。

生成页面时必须同时读取两个文件：

1. 本文件决定“展示什么、允许做什么、如何流转”。
2. 导演规则决定“使用什么结构和组件、如何呈现与交互”。

## 2. 平台业务定位

Boss Ledger 面向：

- 运营
- 商户
- 审核
- 财务
- 风控
- 客服
- 系统管理

核心任务包括：

- 查询
- 管理
- 审核
- 配置
- 维护
- 导出
- 查看详情
- 处理业务结果

首页是业务数据概览，不是营销页面。

## 3. 页面类型路由

### 3.1 默认路由

| 业务需求 | 默认页面类型 |
| --- | --- |
| 查询、管理、审核列表、配置列表、商户资料、结算记录 | 查询列表页 |
| 查询结果需要汇总指标 | 带查询统计的查询列表页 |
| 经营首页、数据看板、经营分析 | Dashboard |
| 少量字段的新建 / 编辑 | Modal 表单 |
| 中等字段的新建 / 编辑 / 审核处理 | Drawer 表单 |
| 多字段、多分组或复杂任务 | Full-page 表单 |
| 普通列表行详情 | Drawer 详情 |
| 开通、配置、规则创建等连续任务 | 分步流程页 |
| 提交成功或失败反馈 | Result 页 |
| 整页无数据、无权限或缺少前置条件 | 空状态页 |

查询类需求未明确页面类型时，默认选择查询列表页。

### 3.2 表单字段数量路由

- 6 个及以下字段：Modal。
- 7–10 个字段：Drawer。
- 超过 10 个字段：新 Tab 或 Full-page Form。
- 11 个字段的复杂页面可以包含说明插图。
- 12 个及以上字段优先使用纯表单布局，不使用插图干扰任务。
- 必填字段显示必填标记。
- 可选字段不显示必填标记。

字段数量只是默认路由。存在复杂联动、长说明、分组校验或独立流程时，可以升级为更完整的页面类型，但不能降级为容纳不足的载体。

### 3.3 详情路由

- 普通列表行详情默认使用 Drawer。
- 详情字段按业务含义分组。
- 只有复杂详情、独立流程或用户明确要求时，才打开新 Tab 或 Full-page Detail。

## 4. 查询列表业务规则

查询列表页必须具备：

- 查询条件
- 查询结果
- 分页
- 列显隐能力
- Loading
- Empty
- Error
- 行内操作

默认规则：

- 默认每页 10 条。
- 查询条件 6 个及以下全部展示。
- 超过 6 个条件时支持展开 / 收起。
- 分页始终归属于当前查询结果。
- 表格字段来源于业务对象，不生成与业务无关的展示列。
- 空结果与请求失败必须区分。

### 4.1 查询条件语义

- 输入型字段使用“请输入字段名”。
- 选择型字段使用“请选择字段名”。
- 日期范围使用明确的开始日期和结束日期。
- 条件展开 / 收起不改变已输入的值。
- 重置恢复页面定义的默认查询条件。
- 查询只影响当前页面对应的数据范围。

### 4.2 查询统计

- 只有需求明确存在汇总指标时才启用查询统计。
- 统计指标属于当前查询条件命中的结果集。
- 无统计时展示普通查询结果标题。
- 有统计时，统计信息替代普通结果标题，避免语义重复。
- 指标标题必须包含单位，例如：
  - `实收总金额(元)`
  - `订单总量(单)`
  - `门店总数量(家)`
- 数值本身不重复追加单位。
- 查询统计只适用于列表结果，不复用为 Dashboard 经营指标。

### 4.3 表格字段

- 金额字段必须明确币种或单位。
- 金额列标题使用 `(元)`、`(日元)` 等明确单位。
- 状态字段使用中文业务状态。
- 操作列位于业务字段之后。
- 操作项必须来自当前记录状态、用户权限和业务流程。
- 不为不存在的操作预留空列或空入口。

### 4.4 行内操作优先级

- 每行必须确定一个最高频或最主要操作。
- 主要操作示例：
  - 查看详情
  - 审核
  - 办理入住
  - 修改房价
  - 对账结算
- 其他操作按频率和风险排序。
- 低频操作进入“更多”。
- 无权限操作按产品约定隐藏或禁用并说明原因。

### 4.5 批量操作

- 批量操作只有在记录可多选且业务允许批处理时出现。
- 未选择记录时不在页面常驻教学提示。
- 用户触发批量操作但未选中记录时，给予即时反馈。
- 批量操作必须校验所选记录是否满足同一业务前置条件。

## 5. Dashboard 与经营分析

- Dashboard 用于业务概览、渠道分布、趋势分析和经营指标。
- 不增加营销内容或无业务依据的快捷入口。
- 一个汇总模块只能有一个核心总指标。
- 子指标最多 8 个；超过时拆分为新模块、排行或列表。
- 不同指标必须明确统计口径、时间范围和单位。
- 筛选条件变化后按产品约定自动刷新当前视图。
- 图表必须绑定真实业务指标与维度，不使用无含义占位数据作为正式结果。

## 6. 表单业务规则

### 6.1 字段定义

每个字段至少应定义：

- 字段名称
- 数据类型
- 是否必填
- 默认值
- 可选值来源
- 校验规则
- 权限
- 是否可编辑
- 错误提示
- 提交映射

### 6.2 字段联动

- 字段联动必须明确触发条件和影响范围。
- 隐藏字段不得以旧值继续提交，除非业务明确要求保留。
- 上游字段变化导致下游选项失效时，应清空或要求重新选择。
- 远程选项加载失败时，不得把空列表误判为“无可选值”。

### 6.3 提交

- 提交前执行必填、格式、范围、关联和权限校验。
- 提交中防止重复操作。
- 提交成功后进入明确的业务结果。
- 提交失败时保留用户已填写内容，并说明可恢复方式。
- 新建、编辑和审核必须区分提交后的状态变化。

## 7. 状态、权限与敏感操作

### 7.1 状态

- 状态值必须来自业务枚举。
- 页面文案使用中文状态。
- 状态显示与可执行操作保持一致。
- 不允许出现“状态已结束但仍可执行进行中操作”等冲突。
- 未知状态不得静默映射为正常状态。

### 7.2 权限

- 权限控制同时作用于页面、字段和操作。
- 无页面权限时显示无权限结果。
- 无字段权限时按业务约定隐藏或脱敏。
- 无操作权限时隐藏，或禁用并提供原因。
- 前端权限表现不能替代服务端校验。

### 7.3 敏感操作

涉及以下对象时，应根据风险等级增加确认或身份校验：

- 账户
- 银行卡
- 结算
- 身份
- 密码
- 风控
- 退款
- 资金划转

可用校验方式：

- 密码校验
- 短信校验
- 行为验证码
- 二次确认

敏感操作确认必须展示：

- 操作对象
- 影响范围
- 金额或数量
- 是否可撤销
- 操作后的状态

## 8. 金额、数量与单位

- 金额字段必须定义币种。
- 金额显示与提交精度必须一致。
- 金额统计口径必须说明是否含退款、手续费、优惠或税费。
- 数量字段必须定义最小值、最大值和是否允许小数。
- 单位写在字段标题或统计标题中，不在同一数值后重复追加。
- 导出数据与页面数据使用同一金额精度和单位口径。

## 9. 结果与反馈

### 9.1 Result

Result 必须说明：

- 操作是否成功
- 业务对象
- 关键结果
- 下一步可执行操作

成功结果不等同于最终业务完成时，应明确后续状态，例如“已提交，等待审核”。

### 9.2 Empty

区分以下空状态：

- 查询无结果
- 首次暂无数据
- 无权限
- 缺少前置配置
- 数据加载失败

不同空状态不能共用同一句“暂无数据”。

### 9.3 反馈

导出、刷新、提交、退款、结算等动作必须反馈：

- 已开始
- 处理中
- 成功
- 失败及恢复方式

## 10. 中文业务文案

- 默认运行时文案全中文。
- 字段、状态、单位和错误信息使用业务人员可理解的表达。
- 禁止直接展示后端枚举值、错误堆栈或英文默认错误。
- 错误文案说明“发生了什么、影响什么、下一步怎么做”。
- 按钮文案使用明确动作，不使用“确定”代替具体业务行为，除非处于通用确认场景。

## 11. 特定业务规则

### 11.1 新品报备

- 商品状态仅允许：
  - `预售`
  - `待发售`
- 合作供应商来自同步供应商列表。
- 日元采购单价保留 2 位小数。
- 预售库存必须为正整数。
- 提交成功后进入 Result。
- Result 支持：
  - 继续新增
  - 返回列表

### 11.2 结算记录查询

- 统计总金额和总笔数属于当前查询条件命中的结果集。
- 行操作包括：
  - 查看详情
  - 下载回单
- 回单不可用时，应明确说明未生成、生成中或无权限，而不是提供失效下载入口。

## 12. AI 业务生成约束

生成前必须：

1. 确认业务对象。
2. 确认用户角色与权限。
3. 选择唯一主页面类型。
4. 定义字段、枚举、单位和校验。
5. 定义状态与允许操作。
6. 定义成功、失败和空状态。
7. 再按照导演规则组装页面。

禁止：

- 在没有业务依据时虚构字段、状态、指标或权限。
- 把不同业务对象混入同一列表。
- 让状态与操作互相矛盾。
- 用视觉占位替代真实业务结果。
- 默认把敏感操作当作普通提交。
- 将普通详情升级为新 Tab，除非复杂度或流程要求明确。
- 将经营首页生成成营销落地页。

## 13. Business Self-Check

交付前检查：

- 是否明确业务对象、角色和目标。
- 是否选择了正确且唯一的页面类型。
- 字段是否包含类型、必填、来源、默认值和校验。
- 枚举值与页面文案是否一致。
- 金额、数量、币种和单位是否明确。
- 统计是否对应当前查询口径。
- 状态与可用操作是否一致。
- 是否处理无权限、无数据、失败和缺少前置条件。
- 敏感操作是否有适当确认或身份校验。
- 提交成功后是否定义下一步。
- 特定业务规则是否完整落实。
- 是否未混入视觉 Token、组件样式或 CSS 实现细节。
